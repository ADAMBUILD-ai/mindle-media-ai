## 앞선 검토가 충분하지 않았던 이유

코드 계약, 실제 모델 실행 여부, MP4 생성 여부를 확인하는 것만으로는 모델이 입력을 이해하고 필요한 판단을 했다는 증거가 되지 않았다. 실제로 영상의 `AI 자동 편집` 버튼은 OpenCV 수치 측정과 FFmpeg의 결정론적 편집 경로로 연결돼 있었다. 내부적으로 model_inference=false를 기록하고 툴팁에 설명했지만, 버튼 이름과 사용자의 기대에 맞지 않았다.

이 문제를 실제 모델 호출 경로로 바꾼 뒤 고정된 기존 Qwen 1.5B를 직접 실행했다. 어두운 입력과 밝은 입력 모두에 보정 0을 반환했고, 31이라는 노출값을 정상 범위라고 설명하기도 했다. JSON 형식·엔진 호출·MP4 생성은 성공할 수 있었지만 **입력에 따른 판단 Gate는 FAIL**이었다. 이 실패를 지우거나 전체 AI PASS로 승격하지 않았다.

## 바로 실행한 보강

1. **AI 자동 편집 버튼을 실제 모델에 연결:** 실제 프레임의 노출·움직임·선명도 측정 → 고정 로컬 Qwen → 구간·보정값 판단 → FFmpeg → 기술 검수 → 저장으로 연결했다.
2. **일반 편집 대체 금지:** 모델이 없으면 `LOCAL_GENERATIVE_MODEL_UNAVAILABLE`로 종료한다. UI 모듈 누락 경로에서도 자동 편집을 일반 함수로 대신 처리하지 않는다. 명시적인 하이라이트 도구는 일반 도구로 보존했다.
3. **판단을 입력에 결속:** input job·원본 SHA, 측정한 시간 구간, 실제 모델 응답 bytes, 반환 결정과 실행 단계를 대조한다. 다른 영상, 변조 응답, 임의 구간, 과도한 보정, 부가 작업을 거부한다.
4. **판단의 적절성 검사:** 측정한 심한 과소·과다 노출을 보정 0이나 반대 방향으로 처리하면 실행 전에 거부한다. 보정값을 코드로 대신 만들어 주지 않는다. 실제 값과 설명은 모델이 반환해야 한다.
5. **결과 검수 후 게시:** H.264·길이·실제 디코딩 표본을 확인하고, 과반 프레임의 노출이 검수 범위를 벗어나거나 노출 오차가 개선되지 않으면 실패 처리한다. 완료 프로젝트·공개 작업 목록을 갱신하지 않는다.
6. **실패한 추론도 보존:** 원시 응답과 REJECTED 사유를 저장한다. 추론 사실과 판단 적절성, 실행 성공과 작품 품질은 분리한다.
7. **다중 GGUF 파일과 자원 검사:** 분할 가중치 모두의 SHA를 검증하고 context 범위를 제한한다. 두 번째 파일이 달라져도 첫 파일 해시만으로 통과하지 못한다.
8. **정확한 지시 보존:** 기존 수치·원고·음량·연장 정책 보호를 유지했다. 건축 영상 지시에서 따옴표 원고 안의 `30초`, `9:16`을 영상 길이·비율 명령으로 오인하던 경로도 수정했다.
9. **표시 교정:** FFmpeg 필터 버튼의 `AI 효과`를 `영상 효과`로 바꿨다. 레이아웃·색상·숏폼 영역은 재설계하지 않았다. 작업별 AI 편집 실행 확인과 전체 제품 인수는 구분해 표시한다.
